离线知识库

内网文档问答：分块、中文分词、BM25 + TF-IDF 双路召回，权限落到文档级。

角色：后端 · 检索与权限 公开

背景

企业文档散在共享盘和 OA 里，同事找一个条款要翻十几份 PDF。要求很硬：数据不出内网，不能调任何外部接口。

做了什么

  • 分块按标题层级切，保留「这份文档的哪一节」这层信息，回答里能回指原文位置。
  • 中文分词后做 BM25 与 TF-IDF 双路召回，再合并排序；纯词频召回对长文档吃亏，双路互补。
  • 权限不在界面层判，落在文档级：检索时就带上用户可见的文档集合，越权命中根本不会进候选。
  • 入库脚本与问答服务分开，加文档只跑脚本，不动服务。

验证

内网独立部署，问答全流程零外网请求；权限按文档生效，检索结果里不会出现用户没权限的段落。

同一个文档链接，普通员工身份打开是 403（当前角色无权查看该文档），换个角色才返回 200。权限不是在界面上藏起来，服务端就不给。

结果 仓库 421 行纯标准库，零第三方依赖；全程不联网，问答只在企业内网里跑。

技术栈

  • Python
  • RAG
  • BM25
  • 向量检索
  • 权限模型
